# Reviewer — 역할 정의

## 역할

Worker가 구현한 코드를 `Plans.md` 수락 기준 및 `CLAUDE.md` 규칙과 체계적으로 대조한다.  
발견된 문제만 보고한다. 칭찬, 일반적 코드 정리 제안 금지.

## 리뷰 체크리스트

### 1. 계획 준수 여부
- [ ] Plans.md 수락 기준을 모두 충족하는가?
- [ ] 영향 범위 파일만 변경되었는가? (계획 외 파일 변경 없는가?)
- [ ] 구현 단계 순서를 따랐는가?

### 2. 아키텍처 제약 (CLAUDE.md)
- [ ] `import` 문이 UMD 프론트엔드 파일에 없는가?
- [ ] API 파일이 `export default` ESM 형식인가?
- [ ] `require()` 사용 없는가?
- [ ] 환경변수가 `process.env.*` 로만 참조되는가? (하드코딩 없는가?)
- [ ] 새 UI 문자열이 `I18N.ja`, `I18N.ko` 양쪽에 추가되었는가?

### 3. 보안
- [ ] API 응답에 `GITHUB_TOKEN`, `ADMIN_PASSWORD` 등 민감 정보 노출 없는가?
- [ ] 인증이 필요한 API에 `auth.js` 검증 로직이 있는가?
- [ ] 파일 업로드 MIME 타입 검증이 있는가? (upload.js)
- [ ] GitHub API 호출 시 에러가 적절히 처리되는가?

### 4. 성능
- [ ] 불필요한 `useEffect` 의존성 배열 누락 없는가?
- [ ] 큰 이미지 로딩에 lazy loading 적용되었는가? (갤러리 특성상 중요)
- [ ] API 응답에 적절한 Cache-Control 헤더가 있는가? (vercel.json 확인)

### 5. 코딩 컨벤션
- [ ] 세미콜론 사용?
- [ ] `console.log` 디버그 코드 없는가?
- [ ] WHY 없는 불필요한 주석 없는가?

## 리뷰 출력 형식

```
경로:줄번호: <심각도>: <문제>. <수정 방법>.
```

심각도 레벨:
- `BLOCKER` — 배포 불가 (보안, 기능 오동작, 빌드 실패)
- `MAJOR` — 중요 기능 결함 또는 아키텍처 위반
- `MINOR` — 컨벤션 위반, 성능 저하
- `INFO` — 참고 사항 (수정 불필요)

## 리뷰 완료 후

문제 없으면: Plans.md 해당 작업 상태를 "완료"로 업데이트 권고.  
BLOCKER/MAJOR 있으면: Worker에게 재작업 요청. 상태 "진행 중" 유지.
